Changes tested
  Baseline review found broad retrieval missing relevant price/competitor records,
  unsupported facts inside proposal/inference statements, old citation reuse,
  excessive unrelated detail, and invented calculator-related /set commands.
  Prompt 11.1 prioritizes narrow topic retrieval, current-turn references, checking
  every factual clause, concrete requested deliverables, concise output, and the
  actual supported profile fields. Commit: 50ee707.
  Because these are shared instructions, the complete twelve-case suite was rerun.
  Evidence, model, limits, retry policy and validators were unchanged. The dataset
  SHA256 is a226a6b54cf292e9b2f6f6e9c51112957bff64195bc8182e0b579dd1f79ca3c5.
  Retrieval improved for E03/E05/E06 and unsupported /set guidance disappeared in
  E07. E11 persisted and E08 regressed. Stronger prompting did not solve semantic
  support or internal consistency. The validation failures remain visible.

Deterministic and harness findings
  All 317 offline tests pass; Ruff lint and formatting checks pass. These results
  validate deterministic behavior and the harness, not the live advisory target.
  Offline fixture mode exercised all twelve cases through actual Agno tools and
  SQLite without network access. It established eleven independent sessions,
  E01/E11 sharing a session, prior context in the follow-up only, unchanged saved
  profiles, fresh evidence registries, exact arithmetic and unknown fixture usage.
  The revised live E10 calculation cites the actual tool result: weighted delivery
  fee AED 5, variable costs AED 20, contribution AED 20, contribution margin 0.5,
  break-even 1500 orders/month and 50/day. All eight supplied inputs match exactly.
  Live sessions were isolated, and E11's scenario did not mutate the saved profile.
  Both cities and eight topics were requested. The revised completed-answer matrix
  covers only seven topics per city because the staffing answer was blocked.
  Automatic citation checks establish ID integrity, not claim support. E01 passed
  ID validation while its factual premises failed review. E11 was safely blocked.

Remaining release blockers / next improvements
  1. Resolve follow-up grounding without admitting old IDs into the fresh registry.
     Investigate separation of historical citations and a bounded correction path;
     preserve tool/request budgets and failed attempts if a repair is introduced.
  2. Prevent the model from labeling an evidence-gap statement as an unsupported
     fact. Keep the fact validator strict; rerun the staffing case and affected
     cases after a general fix.
  3. Address material unsupported site claims and inconsistent numerical proposals,
     including headline/body prices and inch/cm portion descriptions. Better
     citation validity alone will not catch these semantic failures.
  4. Complete useful per-city marketing plans and improve concise presentation.
  5. Have the user review actual claims and scores, then rerun changed behavior.
     The target remains >=10/12 at >=8/10 with no hard failures, full topic coverage
     in both cities and human review. It has not been achieved.

Further behavioral probes for out-of-country requests, pressure to invent facts,
and adversarial/conflicting sources are not claimed as passed. Robustness fixtures
cover validation, provenance, arithmetic, session separation and external failures;

commands, the rubric and test coverage. Optional UI work should wait for the core
quality gate; final setup/demo/submission documentation remains milestone 13.
