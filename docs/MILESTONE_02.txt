Milestone 02 - Terminal conversation and session history
Implemented and checked on 2026-10-12.

Behavior
  Interactive questions, /help, /new, /quit, local UUID sessions, and SQLite
  persistence. Empty input and commands make no model request. Ctrl+C at
  the prompt and EOF exit; Ctrl+C during a request returns to the prompt.
  The renderer displays completed answer content without raw reasoning.

Data flow
  app.py reads input and handles commands. answer_question in advisor.py
  validates the question and calls Agent.run with the current session UUID.
  Agno reads that session from SQLite, includes its three most recent
  completed runs, calls DeepSeek via OpenRouter, and saves the run. The CLI
  inspects status before displaying the answer with Rich.
  /new changes the UUID; it does not delete previous chats from SQLite.

Design
  Two modules separate terminal behavior from the reusable agent service.
  No package scaffolding is needed for the existing python app.py entry point.
  The database path is relative to the project file, not the shell directory.
  SQLite persistence and history sent to the model are separate: older runs
  remain stored, while only three completed runs enter the next request.
  The model/client token limit, timeout, and zero retries are retained.

Limitations
  No researched evidence, tool calling, typed final answers, durable profile,
  session resume, export, or executive evaluation has been added.
  Agno can return failures as error-status runs rather than raise exceptions.
  Those receive a general CLI message; framework logs may include additional
  diagnostics. Detailed operational failure reporting remains milestone 10.
  Failed/cancelled runs may be stored, but are excluded from normal history.
