UAE Market Expansion Advisor

Requirements
  Python 3.12 and uv.
  An OpenRouter API key with access to deepseek/deepseek-v4.1-flash and
  sufficient credits. Get a key at https://openrouter.ai/settings/keys.

Setup (run inside this project directory)
  uv sync --locked
  cp .env.example .env
  Edit .env and set OPENROUTER_API_KEY to your key.

Run
  uv run python app.py

Commands
  /help  Show supported questions and commands.
  /new   Start a fresh conversation with no previous chat context.
  /quit  Exit. Ctrl+D or Ctrl+C at the prompt also exits.
  Ctrl+C during a request cancels it and returns to the prompt.

Example conversation
  Give me two Dubai areas to investigate for a takeaway pizza and kebab branch.
  Name relevant competitors, cite the research, and explain what is unknown.
  Now do the same for Abu Dhabi.
  /new
  We are considering a takeaway branch in Dubai. What information do you need?
  How would those questions change for Abu Dhabi?
  /new
  Using hypothetical inputs: revenue 40 AED per order, food cost 12,
  packaging 2, other variable costs 1 excluding commission, delivery share
  50%, delivery commission 25%, monthly fixed costs 30,000 AED, and 30
  operating days, calculate contribution, margin, and break-even for Dubai.
  Keep those costs and change revenue to 42 AED. Calculate again.
  Expected first result: weighted delivery fee 5 AED/order, contribution
  20 AED/order, margin 50%, break-even 1,500 orders/month and 50 orders/day.

Current behavior
  Interactive terminal chat through Agno and DeepSeek V4.1 Flash on OpenRouter.
  Each launch and /new creates a UUID session. Chats persist locally in
  runtime/sessions.db, which Git ignores. /new keeps stored chats but starts
  with empty context. Agno includes the three most recent completed turns
  from the same session in each request; older stored history is not sent.
  A missing key exits before making a model request. Existing environment
  variables take precedence over .env. Blank input and commands make no
  model request. Questions over 8,000 characters are rejected locally.
  A progress indicator appears while waiting; only completed answers are
  displayed, with Markdown formatting and without raw model reasoning.
  The research tool retrieves curated observations with source links, dates,
  and qualifiers. Each question gets a fresh evidence/calculation registry;
  factual follow-ups must retrieve their supporting records again.
  A second typed Python tool calculates weighted delivery commission,
  contribution per order, contribution margin, and operating break-even.
  All eight numeric inputs are required: revenue, food cost, packaging,
  other variable costs, delivery share, commission rate, monthly fixed costs,
  and operating days. Use explicit zero where appropriate. The agent asks
  for missing inputs or labels an explicitly requested hypothetical example.
  Identify whether inputs are user-provided, sourced, or hypothetical.
  Rates use fractions (0.25 for 25%) inside the tool. Operating days must be
  an integer from 1 to 31. Invalid/nonfinite numbers produce no calculation.
  Revenue is net of discounts and pass-through tax. Commission applies to
  that revenue on delivery orders; other variable costs exclude that fee.
  Fixed costs exclude costs already included per order. Different contract
  bases or extra fees require normalized inputs or an explicit limitation.
  Decimal arithmetic retains precision until display. Currency and percentage
  displays round half-up to two decimals; break-even uses unrounded amounts
  and rounds orders upward. Positive contribution with zero fixed costs gives
  zero break-even orders. Zero/negative contribution produces the viability
  value not_viable_under_inputs and null break-even values, with a warning.
  Status remains ok for this valid computation; it does not mean the business
  is viable. The result includes a generated calculation ID, all inputs,
  formulas, outputs, and warnings. The complete result enters the turn registry.
  Agno requests a native JSON schema and parses output into AdvisorAnswer:
  kind, cities, headline, sections, assumptions, next_steps, and questions.
  Statements identify facts, inferences, proposals, assumptions, or calculations.
  Facts must reference curated records returned during this question; calculations
  must reference successful results from this question. Research leads are
  reserved for the later search implementation and currently fail validation.
  The application generates numbered source links from the registry, retains
  source qualifiers and review flags, and renders exact calculator inputs/results.
  Model text is plain text; model-supplied web URLs fail validation.
  Advice needs a substantive section and a next step; clarification needs a
  question. Sections/items/text are bounded, with at most two questions.
  A post-hook rejects invalid answers before they are stored as completed runs.
  Validation errors log a category and return a recoverable message. The service
  validates again before rendering. Failed answers are excluded from successful
  conversation history; there is no automatic answer repair call.
  OpenRouter receives provider.require_parameters=true through extra_body,
  so routing requires support for our requested parameters. Only the selected
  model is requested; no cross-model fallback is configured. Morph is the
  preferred provider after a successful inspected native-schema/tool turn;
  compatible same-model provider fallback remains enabled.
  Model requests have a 45-second timeout, a 4,096-token completion limit,
  and no automatic client or agent retries. Failed and cancelled runs return
  to the prompt. Agno may log provider diagnostics and return an error status;
  the CLI then shows a general failure message instead of an answer. Raised
  provider exceptions receive HTTP-specific guidance.

How the code works
  load_dotenv loads the local API key.
  OpenRouter configures the gateway, exact model ID, token limit, and timeout.
  advisor.py creates the Agent, configures SqliteDb and history, and exposes
  answer_question(question, session_id, agent) as the shared service boundary.
  turn_tools.py wraps local retrieval and economics.py's calculator. Agno converts typed
  parameters and docstring into the tool schema; the model requests a call,
  Agno executes the Python function, then sends its result back to the model.
  A user turn can therefore make multiple paid model requests. Tool execution
  is bounded to six calls shared by both tools per turn. Tools make no model requests.
  TurnRegistry holds only returned evidence and valid calculation results,
  including nonviable scenarios. Each calculation entry stores the complete
  status/data/warnings envelope; result.calculations[id]["data"] holds its values.
  It is injected through Agno RunContext dependencies and is not model input.
  answers.py defines the response schema, reference checks, and Markdown renderer.
  answer_question returns ApplicationResult with the validated answer, rendered
  Markdown, sources, calculations, warnings, and available usage information.
  app.py handles commands and displays that shared result.
  Agent.run submits a turn and lets Agno manage context and persistence.
  evidence.py validates data/market_evidence.json at startup and provides
  local city/topic filtering with deterministic keyword ranking. Returned
  records retain their source metadata, qualifiers, and freshness flags.
  Both-city lookups interleave results without duplicating shared records.
  Lookups return up to 8 records by default (maximum 12) within an 8,000-
  character serialized JSON result, reporting how many matches were omitted.
  Menu, pricing, competitor, dated-offer, and business/platform location
  records use a 30-day review window; other context uses 180 days. Publication
  and inspection dates both affect review flags. Expired offers are flagged.

Dependencies
  agno: agent framework.
  openai: API client used by Agno's OpenRouter adapter.
  python-dotenv: local environment configuration.
  sqlalchemy: required by Agno's SQLite adapter.
  rich: terminal Markdown and progress rendering.
  pydantic: explicitly declared dependency for typed final answers.
  pytest: development dependency for offline checks.
  ruff: development dependency for linting, import sorting, and formatting.
  uv.lock pins the resolved dependency versions for reproducible installation.
  The SQLAlchemy asyncio extra supplies greenlet because Agno's SQLite module
  imports both adapters, even though this application uses synchronous calls.

Current limitations
  Conversation, the scenario economics calculator, and typed answers are implemented.
  The evidence loader and local retrieval are implemented. The production
  dataset contains 48 manually researched observations from 22 sources,
  inspected on 2026-10-12 UTC, covering all eight topics in both cities.
  data/research_coverage.json records coverage, candidate areas, competitor
  examples, comparison limits, and remaining research gaps. Counts indicate
  initial coverage, not a complete market study. Synthetic records live only
  in tests/fixtures/.
  Local evidence retrieval and citation validation are connected to the advisor.
  Live web search, durable business profiles,
  session resume, exports, and executive evaluations are not implemented yet.
  Calculator scenarios do not prove demand, profitability, or investment
  viability. Hypothetical inputs do not automatically become profile facts.
  Numeric validation cannot prove the model copied the user's intended inputs.
  Instructions require clarification for missing inputs and forbid placeholders;
  review the displayed input table as well as the model's explanation.
  Repeating decimal margins use the calculator's decimal precision; orders
  are calculated directly from unrounded contribution, not from that margin.
  Schema validation checks structure, not factual truth or whether a model's
  explanation correctly reflects a tool result. No answer-repair call or
  separate parser model is used. Native schema failures are not silently
  replaced with another model or an unvalidated plain-text answer.
  A retrieved source ID does not prove that the source supports its attached
  statement. Inferences/proposals and uncited headline/assumption text still
  need semantic review; a model-assigned label is not proof of factual accuracy.
  Local storage alone does not give the model unlimited memory. Failed or
  cancelled runs may be saved for diagnostics; Agno omits them from history.
  Requests use OpenRouter credits. No OpenAI API key is required.

Research maintenance
  Update source observations only after inspecting the actual source page.
  Keep published_on null when no publication date is shown; checked_on is
  the UTC inspection date. Preserve branch, portion, channel, and price qualifiers.
  Recheck menus and branch listings before decisions. The dated Dubai safety
  PDFs and historical Abu Dhabi event report already carry review flags;
  inspection does not turn older material into a current measurement.
  Rent, footfall, demand, wages, commissions, and supplier quotes are gaps,
  not verified numbers. Supplier coverage currently has one company example.
  Update research_coverage.json alongside the dataset when coverage changes.

Offline checks
  uv run pytest -q
  Tests mock inference and use temporary SQLite files. No API credits needed.

  Run the same checks as CI:
    uv run ruff check .
    uv run ruff format --check .
    uv run pytest -q -m "not integration"
    uv run pytest -q -m integration

  Fix imports/lint issues and apply formatting locally:
    uv run ruff check --fix .
    uv run ruff format .
  Review the fixes before committing; some lint issues need manual changes.

  GitHub Actions runs three independent jobs on pull requests and main pushes:
  lint/formatting, unit tests, and integration tests. Each uses uv.lock.
  Integration tests carry @pytest.mark.integration and exercise real Agno
  flows or SQLite persistence while replacing model inference. All other
  tests run in the unit job. Unknown markers fail collection to catch typos.
  A plain pytest run still runs both groups. CI checks formatting without
  rewriting code; apply formatting locally before submitting changes.
